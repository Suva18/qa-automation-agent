# Test Case Design

Use when a requirement, defect fix, or recurring workflow needs reproducible coverage.

## Core

Map every case to a requirement or risk, keep one intent per case, and define observable expected results. Use explicit synthetic data and independent preconditions. If behavior is undefined, raise a requirement question rather than inventing an oracle.

## Optional Reference

For technique selection, coverage reduction, negative cases, traceability, and quality checks, load [test-case-design reference](../references/skills/test-case-design.md). Skip it for a small, already-specified case.
