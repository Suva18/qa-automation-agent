# API Testing

Use for HTTP/service contracts, access control, persistence effects, or integration boundaries.

## Core

Confirm the authoritative contract, use isolated identities and synthetic data, and validate response semantics plus resulting state. Forbidden requests must create no side effect. Do not fuzz, enumerate, load test, or probe authorization outside explicit scope.

## Optional Reference

For comprehensive contract, behavior, failure, access, async, side-effect, and operational coverage, load [API-testing reference](../references/skills/api-testing.md). Skip it for one narrowly defined endpoint assertion.
